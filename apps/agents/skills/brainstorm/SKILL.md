# 头脑风暴（创意发散）

进入创意发散模式。**禁止使用 write/edit 工具**，只做创意生成和分析。

## 核心理念

LLM 天然倾向于生成训练数据中高频出现的"安全答案"——这些通常也是最显而易见的答案。本 Skill 的核心目的是**用结构化流程迫使模型跳出插值区域，进入真正的"发散空间"**。

达成这一点的关键在于三条硬规则：

1. **发散和评判严格分离**：Diverge 阶段禁止任何形式的评判，评判只能在 Evaluate 阶段进行。
2. **前三个最显而易见的答案必须跳过**：如果某个想法你第一时间就想到了，标记它然后继续往下挖。
3. **数量是新颖性的前提**：第 15-30 个想法往往才是金子。

## 目标

1) 理解用户的创意需求，明确问题域、约束条件和成功标准。
2) 使用多种创意技术系统性地生成大量想法（≥10 个），标记类型。
3) 聚类、评估并收敛到最值得探索的方向，输出可操作的收获结果。

## 流程

### Phase 0: 准备 (Setup)

在正式开始前，完成以下准备：

1. **明确问题域**：用户想探索什么？限制条件是什么？成功标准是什么？
2. **信息缺口检查**：如果信息不足以有效发散，最多问 3 个澄清问题。一次只问一个（参考 plan skill 的交互模式），附推荐答案。
3. **选择创意技术**：根据问题特征，从 `references/techniques.md` 中预选 ≥2 种技术。优先选择能带来不同视角的组合。

### Phase 1: 发散 (Diverge)

这是整个流程的核心。规则如下：

- 使用 ≥2 种预选技术，每种技术生成 ≥5 个想法，总计 ≥10 个。
- **绝对禁止评判**：不评价好坏、不分析可行性、不比较优劣。这阶段唯一的目标是**数量**。
- **跳过明显答案**：前 3 个最显而易见的想法允许记录但必须标记，继续往下挖。
- **标记类型**：每个想法标注 `[N]` 新颖 / `[V]` 常规但可行 / `[W]` 疯狂（可能不可行但值得记住）。
- **每个想法附带推导链**：一句话说明这个想法是从哪个技术的哪个角度推导出来的。

具体技术的使用说明见 `references/techniques.md`，发散阶段的 prompt 模板见 `references/prompts.md`。

### Phase 2: 聚类 (Cluster)

将 Phase 1 生成的想法按底层角度（而非表面关键词）分组：

- 产出 3-6 个簇。
- 每个簇用一个角度标签命名（如"去掉中间层"、"从用户情绪切入"、"把约束反过来"），而不是按表面主题（如"前端方案"、"后端方案"）。
- 将每个想法归入对应簇中。

### Phase 3: 评估 (Evaluate)

对每个想法进行三维评分（0-10）：

| 维度 | 说明 |
|------|------|
| **新颖性** | 离显而易见的默认答案有多远 |
| **可行性** | 能否实际落地 |
| **匹配度** | 是否针对用户提出的问题 |

额外检查：
- **陷阱标记**：对看起来很美但隐藏重大问题的想法，标注陷阱类型（隐藏成本、不可扩展、假经济性、过早抽象等）并附一行说明。
- **[W] 标签重评估**：疯狂想法中有没有通过某种约束调整就能变可行的？

### Phase 4: 收获 (Harvest)

输出结构化的收敛结果：

1. **Top 3 精选**
   - 加权排名（新颖性 ×0.35 + 可行性 ×0.40 + 匹配度 ×0.25），排除陷阱。
   - 每个精选附 **2-3 句选中理由**，明确说明它为什么值得优先探索。

2. **下一步行动**
   - 为每个 Top 3 想法给出一个**具体的下一步**——比如快速原型、用户访谈、竞品调研、技术验证。

3. **停车场**
   - 2 个当前暂缓但有潜力的想法，附说明为什么暂缓（时机不对、依赖未满足、超出当前范围等）。

## 执行规则

- 你可以使用 ask_user 来在 Setup 阶段澄清问题，但要注意一次一问。
- Phase 1 和 Phase 2 之间**绝不穿插评判**。如果你发现自己在 Diverge 阶段产生评判冲动，提醒自己"先记下来，到 Phase 3 再说"。
- 如果用户中途想调整方向（比如缩小范围、切换技术），回到 Phase 1 重新开始。
- 发散和评估不需要等待用户确认，可以在一个回复中连续完成整个流程（Setup 中的提问除外）。

## 退出创意发散模式

当完成 Harvet 输出后，向用户确认是否退出创意发散模式。若用户确认，则退出；否则继续探索。
