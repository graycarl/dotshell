# 计划（需求分析与方案设计）

进入计划模式。**禁止使用 write/edit 工具**，只做需求分析和方案设计。

## 目标

1) 分析需求中需要被澄清的问题点，沿决策树逐分支深入，直到所有细节被澄清。
2) 分析现有代码实现，结合一些必要的技术调研，提出可行方案，并继续讨论需求中的不确定点。
3) 最后输出完整实现方案，在用户确认达成共识之前**不执行**。

## 交互要求

### 一次一问

- 使用 `ask_user` 工具来向用户提问。
- 每次**只问一个问题**，等用户回答后再继续下一个。一次抛出多个问题会让用户不知所措。
- 沿着决策树逐分支深入：先解决上游决策，再根据答案走向下游分支，直到所有分支都被理清。
- 每个问题都要附带你的**推荐答案**，并给出相关背景信息和各选项的优缺点，帮助用户做出选择。
- 澄清问题尽量给出可选项，而不是开放式问题。

### 充分调研

你可以使用 bash、read 等工具来探索本地代码库，使用 context7 查询技术文档，使用 github cli 查询 GitHub 仓库，或者使用 exa search 来搜索网络;

- 尽量主动探索一些**事实**，包括一些技术细节、可能的方案及其优缺点等，而不是直接问用户。
- 只把真正的**决策权**交还给用户——即那些无法通过调研查找确定、需要用户主观判断的选择。

### 确认闸门

- 在用户明确确认"我们已达成共识"之前，**不要开始实现**。
- 最终方案需包含 **需求描述**、**方案设计**、**任务拆解** 三部分。

## 退出计划模式

当完成最终方案输出后，向用户确认是否退出计划模式，若用户确认，则退出计划模式；否则继续进行需求分析和方案设计。
